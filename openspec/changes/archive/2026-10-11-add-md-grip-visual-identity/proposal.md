# Proposal

## Why

MDGrip 已建立独立项目身份，但当前菜单栏仍使用系统符号 `doc.text`，macOS App 尚无自有图标资源，README 也没有品牌图形。先完成一套覆盖 App、仓库与浏览器预览的原创视觉资产，为后续仓库信息优化提供一致的识别基础，而不改变产品功能。

## What Changes

- 建立面向 CLI 与 macOS App 的共同品牌识别：定位为 Markdown 预览工具，以文档与预览窗口融合的简洁几何符号为核心，采用克制的蓝色主色系，图标不含文字；不复用或改造上游图标，不使用许可不明的第三方素材。
- 先提供两个低保真方向，在状态栏小尺寸、App 与仓库展示中比较轮廓和构图；用户选定一个方向后再精修、确定具体色值并接入，不提前精修全部候选。
- 交付同源、分别适配的四类资产：单色 template 状态栏图标；平面为主、保留轻微层次的 App 图标；简化平面的仓库品牌图标；从同一图形派生的网页 favicon。保留共同核心轮廓，按场景调整线宽、留白与细节，不直接缩放同一张图片。
- 替换菜单栏现有系统图标，补齐 App 图标资源并纳入现有打包产物，在 README 顶部最小接入仓库图标，并替换预览网页现有 favicon；保持现有菜单栏交互、预览功能与应用激活方式。
- 将预览网页页脚中的 `Made with ♥ by chrishrb` 替换为 `Rendered with MDGrip`，保持现有页脚位置、样式和显示条件；此项只更正界面品牌文案，不改写 LICENSE 中的上游版权或 README 中的项目来源说明。
- 提交可编辑 SVG 源文件、各使用位置所需的导出资产及简短导出说明，沿用项目 MIT 许可。正常构建直接使用已提交资产，不要求安装设计或图像导出工具。
- 以实际展示验收：正常显示尺寸下的浅色与深色菜单栏、Finder 与应用程序目录、打包后的 `.app` 图标资源、README 浅色与深色背景，以及实际预览网页的浏览器标签和页脚文案。候选评审可用模拟图，但最终接入验收不以设计稿或仅构建成功代替实际观察。

## Capabilities

### New Capabilities

- `project-visual-identity`：定义原创图形的共同识别与场景适配、候选方案选择、源文件和许可交付，以及状态栏、App、README、网页 favicon 的接入、预览网页页脚品牌文案与实际展示验收。

### Modified Capabilities

无。既有 `macos-menu-bar-app` 的常驻宿主、无 Dock 图标及交互要求，以及 `macos-app-packaging` 的架构、签名与分发要求保持不变；本次新增视觉要求由 `project-visual-identity` 承载，不重复定义既有功能契约。

## Non-goals

- 不制作 GitHub 社交预览图，不重设计 README、不重写项目介绍或章节、不更新截图；完整仓库信息优化属于后续独立变更。
- 不制作完整品牌手册、横版字标、吉祥物、DMG 背景或卷图标，不交付 Figma、Sketch 等专有工程文件。
- 不修改 GitHub 个人头像、About、topics 或仓库设置。
- 不新增忙碌、成功、错误等状态栏图形或状态切换机制，不让 App 常驻 Dock，不改变菜单栏、Finder Services、渲染、会话管理或热重载行为。
- 不重设计预览网页；页脚仅替换指定品牌文案，不更改位置、样式或显示条件。
- 不变更项目名称、CLI/module path、Bundle ID、协议或 API，不改变签名、公证与安装信任验证边界，不在本变更中发布新版本。
- 不改写上游来源及已有版权说明，不为图标引入独立许可或额外品牌使用限制。

## Impact

- macOS：`macos/MDGrip/AppDelegate.swift` 的状态栏图像接入、App 图标与菜单栏资源，以及 `macos/MDGrip.xcodeproj/project.pbxproj` 的资源配置。现有构建配置已指定 `AppIcon`，但尚无对应资产目录；新增资源应随现有 App/DMG 打包流程交付，不另建分发流程。
- 网页：替换 `defaults/static/images/favicon.ico` 的嵌入资源，保留 `defaults/templates/layout.html` 已有 favicon 引用路径，并只替换该模板中的指定页脚文案；不改路由、嵌入规则，不引入新的页面功能或外部资源服务。
- 仓库：新增原创 SVG 与导出资产、简短导出说明，并仅在 `README.md` 顶部接入图标；保留现有来源、许可、安装和候选分发说明。
- 依赖与兼容性：图像导出仅用于资产维护，不成为正常构建或运行的新依赖；无 CLI、协议或 API 的破坏性变更。实际验收记录需区分观察结果与未验证环境，不以构建或静态资源检查声称完成未观察的平台验证。
